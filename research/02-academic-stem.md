## Gaps and limitations found in this domain

1. **Premium academic benchmarks skew non-commercial.** SciQ, ReClor, and SciFact are all CC BY-NC — a real recurring pattern. Any commercial redistribution plan needs to segregate these into a "research-only" tier.
2. **Peer-review and citation-intent data have the murkiest licensing of everything surveyed.** PeerRead has no license file at all, collected via reviewer/author opt-in consent rather than copyright license — redistributing wholesale is legally riskier than MC-QA sets. SciCite shows conflicting license signals between HF card and GitHub repo. This sub-area needs direct author contact before inclusion in a redistributable corpus.
3. **Answer-verification (noul) data for math is thin and mostly needs synthesis.** GSM8K/MATH are natively generation-shaped, not decision-shaped; only PRM800K is natively step-level correctness-labeled at scale, and it's math-only — no equivalent large real process-supervision corpus for physics/science/code reasoning steps.
4. **Code-domain coverage is the thinnest of the four sub-areas.** Most well-known code datasets (HumanEval, MBPP, APPS) are generation benchmarks, not classification. Devign/CodeXGLUE defect detection is the one solid binary-classification set found, and carries a non-standard C-UDA license.
5. **Essay/short-answer scoring has inconsistent scales.** ASAP-AES's 8 prompt sets each use different score ranges — a `score` primitive needs real per-prompt renormalization, not a naive shared scale. ASAP-AES (2012, Kaggle rules) and ASAP 2.0 (2024, CC BY) are different datasets with different licenses — don't conflate.
6. **"Open" repo license ≠ clean content provenance.** MMLU and ARC both show permissive license at the wrapper level while underlying exam-question text was authored elsewhere (textbooks, professional exams) — worth stating explicitly rather than treating repo-level license as the whole story.
